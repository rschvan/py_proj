Getting Started

PyPathfinder creates, analyzes, and displays Pathfinder Networks from proximity data: distances, dissimilarities, or relatedness values between every pair of a set of terms. The app has three pages, listed in the sidebar: Build Nets, View Network, and Help.

Sample proximities and networks are loaded when the app starts, so you can try everything before using your own data. A typical session goes like this:

  1. Add data. On Build Nets, click Add Data Files… in the sidebar. The minimum Pathfinder network (q = r = ∞) is derived for each file automatically.
  2. Derive more networks if you want them: select proximities in the Proximity List and use Derive Networks… to choose q and r, or a Nearest Neighbor network.
  3. Look at a network. Select one network in the Network List and click Display Network.
  4. Adjust the layout on View Network: try layout algorithms, flip or rotate the picture, and drag nodes. Click Save Layout to keep a layout you like.
  5. Save the project with Save Project in the sidebar so you can reload your work later.
Save your work. The app loses its data when it is left idle for a while (the server goes to sleep). Save your project before a break and load it again when you return. See Saving & Loading Projects.

Click Clear Demo in the Build Nets sidebar to remove the sample data, along with networks and averages made only from it (an average that also used your own data is kept). Load Demo adds the sample data again. While it is loaded, Save Project saves it with your work. The Getting Started panel on Build Nets can be hidden by clicking its header.

Build Nets Page

Adding proximity data

Click Add Data Files… in the Build Nets sidebar. In the window that opens, pick the file type (Spreadsheet or Legacy Text), and browse for or drag in one or more files. The window closes when the files have been added. The part of a file name before the first period becomes the proximity's name; if that name is already used, a number is added to make it unique. Files that cannot be read are listed in an error message. The file layouts are described in Spreadsheet Data Format and Legacy Text Data Format.

Force Proximity Symmetric: when this is on, an asymmetric proximity is made symmetric as it is loaded by using the smaller of the two distances for each pair (dij and dji). This gives undirected networks. The proximity's name gets _fs added.

Select items by checking the boxes to the left of the Name column; checking the box at the top selects or deselects every item. The buttons under each list become active when the selection suits them.

Deriving networks

Select one or more proximities and click Derive Networks… under the Proximity List. In the window that opens, choose the network type (and q and r for Pathfinder networks) and click Derive.

  • Pathfinder networks keep a link between two terms only when no other path between them is shorter. Two parameters control what counts as a path and how its length is measured:
    • q is the most links a path may have when searching for a shorter path. The default, ∞, examines all paths (the longest possible has n−1 links for n nodes). With q = 2, only two-link paths are considered. Smaller q keeps more links.
    • r is the Minkowski exponent used to combine the link distances along a path. With r = ∞ a path's length is its longest link; with r = 1 it is the sum of the link distances; with r = 2 it is the Euclidean combination. Larger r keeps fewer links.
    q = r = ∞ gives the network with the fewest links. Its links are in every Pathfinder network of the same data. If the network is connected and there are no ties in the distances, it is the minimum spanning tree; ties can add cycles. See the Wikipedia page for more detail.
    Names show the parameters: bio_pf, bio_pf_q2, bio_pf_q2_r2.
  • Nearest Neighbor networks link each term to its nearest neighbor (to every term tied for nearest). They are directed, from each term to its nearest neighbor. Names end in _nn.

Averaging proximities

Select two or more proximities with the same terms and click Average Proximities…, then Compute Average in the window that opens. Each cell of the new distance matrix is the mean or median of the same cell in the selected proximities. For the mean, an infinite distance is replaced by 1.1 times the largest finite distance of its proximity. You can give the average a name; otherwise it is named from the first and last proximities averaged. Average names start with !x̄ (mean) or !mdn (median) followed by the number of proximities averaged.

Display Matrix

With exactly one proximity selected, Display Matrix shows its terms and distance matrix.

Network Properties and Link List

With exactly one network selected:

  • Network Properties shows the radius and diameter and, for each node, its degree, eccentricity, and whether it is a center or median node. These measures are defined in Measures.
  • Network Link List lists the links: si and ti are the source and target node numbers (starting at 0), followed by the source and target terms and the link's weight (its distance). For merged networks, the weight is a code showing which networks contain the link (see below).

Merging networks

Select two or more networks with the same terms, click Merge Networks… under the Network List, optionally type a name, and click Merge. The merged network contains every link found in any of the selected networks. Merged names start with ~~mg and the number of networks merged.

The weight of a merged link is a binary code. The networks are numbered i = 0, 1, 2 … in the order they appear in the Network List, and a link's weight is increased by 2i when network i contains it. Reading the weight in binary from right to left, a 1 in position i means network i has the link. The Link List of a merged network shows this code (nets) and how many networks contain each link (count). On View Network, Weights shows the same code on each link, and a legend in the corner (also in the PNG) lists each network with its code. Both show one digit per network, so merging three networks gives codes such as 011 (in networks 0 and 1).

A merged network can't be merged again, because its link codes would be lost. Merge the original networks together instead.

Project files save which networks each merge was made from, and the merge is rebuilt when the project is loaded.

Comparison tables

Turn on the switches under the lists to show:

  • Show Proximity Correlations (under the Proximity List): the correlation between the distances of each pair of proximities.
  • Show Network Similarities (under the Network List): the proportion of shared links for each pair of networks.

Both are computed only for pairs with the same terms; other pairs show None.

Downloading tables and deleting items

Any table can be downloaded as a .csv file: hover over the table and click the download icon in the toolbar at its top right. To delete proximities or networks, select them, click Delete Proximities… or Delete Networks… under the list, and click Delete in the window that opens.

Deleting also removes the networks made from the selection, so no network is left without its source:

  • Deleting a proximity removes its networks and any merged networks they were part of. Averages made from it are kept, with their networks: an average holds its own distances.
  • Deleting a network removes any merged networks it was part of.

The Delete window lists these extra items before you click Delete.

Each of these windows names the selected items at the top. Close a window with × to cancel; it closes by itself when the action is done.

Using Physics

With Physics on, the engine moves the nodes until they settle. If you drag nodes while it is on, you can influence the layout, and you can help remove crossed links, but the engine still decides where nodes settle. Holding a node in a new position often keeps the engine looking for a solution with the node there. Turn Physics off to make the display still again; then dragged nodes stay where you put them.

Layout algorithms

Layouts vary a lot in quality. It is usually worth trying several, using Redraw until a reasonable layout appears, and then dragging nodes to finish it.

AlgorithmDescription
savedThe layout saved with Save Layout for these terms (listed only when one exists).
autoChooses for you: a tree layout for trees, kamada_kawai for up to 100 nodes, and a force-directed layout for larger networks. The header above the display shows which one was used.

kamada_kawaiPlaces nodes so that distances on the page match the number of links between them. A good general choice.

radial_treeThe same tree laid out in circles around the center node.
mds_distanceMultidimensional scaling of the proximity distances, so positions reflect all the distances, not just the links. Useful when all distances are meaningful, as with the geographic cities and statecaps data (statecaps distances are miles between state capitals).
mds_graphMultidimensional scaling of the number of links between nodes.
springA classic force-directed (spring) layout.
spiralNodes placed along a spiral.
planarA layout with no crossing links when the network is planar; otherwise the same as kamada_kawai. For example, the statecaps_pf_q2_r2 sample network is planar.
sugiyamaA layered layout that suits directed networks.

Each network remembers the algorithm chosen for it.

Saving a layout

Click Save Layout in the sidebar to keep the current node positions. The layout is saved for the network's terms, not just for the network, so every network with the same terms can use it by choosing saved in Select Layout Algorithm. This makes it easy to compare networks derived from the same terms (different q and r, different proximities, averages, or merges) with the nodes in the same places. Saving again replaces the saved layout. Saved layouts are stored in project files.

Comparison set

The Comparison Set at the bottom of the View Network sidebar keeps networks you want to switch between. Click Add to put the network in view in the set. All networks in the set have the same terms (the terms of the first one added), so they can share a saved layout. In its table, tick view to show a network (the one in view is ticked) and tick delete to take it out of the set; Clear All empties the set. Each network keeps the layout algorithm chosen for it, so you can go back and forth to compare them. A network deleted on Build Nets leaves the set too. The set is not saved in project files.

Measures

Coherence

Coherence is a correlational measure of the internal consistency of a proximity's distances. It is based on the idea that terms that are near one another should have similar distances to the other terms. For each pair of terms, the profiles of their distances to the other terms are correlated (an indirect measure of relatedness), and coherence is the correlation between these indirect values and the direct distances (sign reversed, so higher means more consistent). With data from human ratings, coherence may reflect knowledge of the terms, as found in studies of expertise and learning. Randomly generated ratings give coherence near zero.

Proximity correlation

The correlation between the distances of two proximities with the same terms, using the lower half of the matrices when both are symmetric and all off-diagonal cells otherwise.

Network similarity

The number of links found in both networks divided by the number of different links found in either (intersection over union). It is 1 for identical networks and 0 for networks with no links in common.

Link rank

The links of a network are ranked by their distance: rank 1 is the shortest distance (the strongest link), rank 2 the next shortest, and so on. Links with equal distances share a rank. For a merged network, rank 1 is the links found in the most networks, rank 2 the next most, and so on.

Network properties

These count links between nodes and ignore link direction.

MeasureMeaning
degreeNumber of links at a node. Directed networks also show indegree (links in) and outdegree (links out). max degree marks the nodes with the highest degree.

Saving & Loading Projects

Use Save Project and Load Project… in the Build Nets sidebar. Saving downloads a .json file named from the Project Name above them; your browser may let you choose another name or folder. Loading opens a window where you choose a project file, choose how to load it, and click Load (or close the window to cancel):

  • Replace current project: start fresh with only the project in the file. Everything loaded now, including the sample data, is removed, so save your current work first if you want to keep it. If the file cannot be read, nothing is changed.
  • Add to current project: keep what is loaded now and add the file's proximities, networks, and saved layouts. Names that are already in use get a number added (for example bio_2).

Spreadsheet Data Format (.xlsx or .csv)

Spreadsheet files are easier to create and simpler than legacy text files, so use this format for new data. With n terms, the spreadsheet has n+1 rows and n+1 columns. The first row contains the terms (node names) starting in column 2, and the first column contains the same terms starting in row 2. The rest is the matrix of distances (or dissimilarities) for the term on the row and the term on the column. A sheet without the header row (n rows and n+1 columns, terms in the first column only) is also accepted. The part of the file name before the first period is the name of the proximity.

Symmetric matrices (where each row equals the corresponding column) give undirected networks; asymmetric matrices give directed networks. The diagonal is treated as zero distance (the distance of an item to itself). Anything other than a number in an off-diagonal cell (a blank, "nan", "inf", text, and so on) is treated as an infinite distance, which means that pair can never be linked.

Values must be distances or dissimilarities: smaller means closer. If your data measure similarity (like correlation or cosine), convert them with d = 1 − s. Similarity or relatedness ratings can be converted with d = min(s) + max(s) − s.

Legacy Text Data Format (.txt)

The legacy text format was used by earlier Pathfinder software and by various methods for creating proximity data, so PyPathfinder can load these files. It supports some options the spreadsheet format does not: sparse data, where only a few pairs have finite distances (the list format gives just those pairs), and distances computed from vectors of coordinates, features, or attributes, one vector per term.

Data and terms files

With legacy files, the proximity data and the terms are in separate text files, with one term on each line of the terms file. Load the data file and its terms file together. Terms files can be named in two ways:

  • terms.txt is used for every data file loaded with it, for a set of data files with the same terms.
  • A terms file for one data file is named after it with .trm added: for data.txt or data.prx.txt, the terms file is data.trm.txt. Recall that the proximity name is the part before the first period.

A data-specific terms file (.trm.txt) takes priority over terms.txt.

Data file layout

The data may be similarities, dissimilarities, probabilities, distances, coordinates, or features. With dissimilarities or distances, smaller numbers mean closer (more similar, more related). The opposite is true of similarities, probabilities, or relatedness: larger numbers mean closer. With distance measures, the distance between an entity and itself (the diagonal of the matrix) is usually 0. All entries must be positive or zero; negative numbers are not allowed. Values outside the minimum–maximum range (see below) will never produce links. A strictly formatted text file is required. Here is a small example:

The lines must be in this order (/ separates alternatives):

LineContents
1The word data in some form ("data", "DATA", "Data") identifies the file type.
2Type of data: similarity / sim / probability / prob / dissimilarity / dis / distance. With similarity data, larger values mean greater similarity; with distance data, smaller values mean closer.
3Number of nodes (terms), an integer. The word "nodes" is optional.
4Comment: a short description of the data. The line is required but not used.
5Minimum data value, a positive number. Words are optional.
6Maximum data value, a positive number. Words are optional.
7Order of the data values: matrix / upper / lower / list / coord / featur / attrib
8 onThe data

For lines 3, 5, and 6, only the first number on the line is used; any following text just labels it.

The minimum and maximum are cutoffs: two nodes whose value is outside the minimum–maximum range can never be linked in any network. Missing data can be handled by using values outside the range, or by using the list format.

Line 7 says how the values that follow are arranged: a full matrix, an upper triangle, a lower triangle, a list, or vectors. The upper and lower (half-matrix) forms leave out the diagonal. With n nodes, a matrix must contain n × n values, and an upper or lower triangle n(n−1)/2 values. Asymmetric data must be given as a matrix, or as a list marked nonsymmetric or asymmetric; symmetric data can use any of the four forms.

With the list form, the line after "list" gives the number of pairs, and the next line says whether the pairs are symmetric or nonsymmetric. Each pair is then three numbers: the source term number, the destination term number, and the proximity value. Term numbers start at 1 (not at 0 as in Python). Pairs not in the list are never linked.

Coordinates, features, vectors, or attributes

When the data are vectors, one for each node, the lines from line 7 on are:

LineContents
7coord / feature / attrib: the data are vectors of numbers, one vector for each node.
8The number of dimensions, attributes, or features in each vector (an integer, optionally followed by a label).
9How distances are computed: euclidean / city block / dominance / hamming / cosine, optionally followed by standardize.
10 onThe vector for node 1, then node 2, and so on.

Here is a small example for 5 nodes in 2 dimensions:

Each of the 5 nodes has a value on each of two dimensions, like points in 2-dimensional space. The number of nodes comes from line 3, and the number of dimensions or features from line 8; there can be any number of dimensions. With coordinates, the data often come from the spatial layout of items. With features or attributes, the data may be ratings of each item on several Likert-type scales, so the scales can be thought of as features. Features can also mark the presence or absence of features with 1s and 0s.

Line 9 decides how distances are computed for every pair of nodes:

  • Euclidean: the straight-line distance between the nodes in multidimensional space.
  • City Block: the sum of the differences between the nodes on each dimension or feature. This is usually the most appropriate method for Likert-type rating data.
  • Dominance: the largest difference between the nodes on any dimension or feature.
  • Hamming: the number of features on which the nodes differ.
  • Cosine: based on the cosine of the angle between the vectors, which ranges from 1 to −1. Because cosine measures similarity, the distance is 1 − cosine, which ranges from 0 (vectors pointing the same way) to 2 (vectors pointing in opposite directions).

With standardize on line 9, each vector is scaled to length 1 before distances are computed. This is often appropriate when the vectors vary greatly in size. For example, with vectors from Latent Semantic Analysis (LSA), Euclidean distances between standardized vectors give a measure very similar to the cosine usually used in LSA work.

A complete example using the City Block method:

data

6 maximum data value

4 dimensions

2 1 3 2

The distance between nodes 1 and 2 (rows 1 and 2) is |2−1| + |1−5| + |3−1| + |2−4| = 9, where |a−b| is the absolute value of the difference. The distance between nodes 2 and 4 is |1−2| + |5−4| + |1−1| + |4−2| = 4. Distances are computed this way for all pairs.

The vector data must have a value on each dimension or feature for every node. Values are separated by one or more spaces or line breaks.
